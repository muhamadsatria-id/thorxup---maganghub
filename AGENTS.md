# cp-site (THORXup)

Company-profile site: Laravel 13 (PHP 8.3+) + Blade + Tailwind CSS 4. `livewire/livewire` is installed but unused. Only `routes/web.php` exists (no `routes/api.php`). This directory is not a git repo, and `README.md` is the stock Laravel readme — trust this file and the config instead.

## Commands

```sh
composer setup       # composer install, .env copy, key:generate, migrate --force, npm install, npm run build
composer dev         # php artisan dev → runs `artisan serve` + `queue:listen` + `npm run dev` together
composer test        # config:clear, then php artisan test (Pest 5)
php artisan test tests/Feature/ExampleTest.php
php artisan test --filter=<test name>
vendor/bin/pint      # formatter; no pint.json, uses the Laravel preset
npm run build        # required when Vite is not running, otherwise @vite has no manifest
```

`php artisan dev:list` shows the dev processes; `php artisan dev --inline` is useful in non-TTY shells.

## Environment and database

- The local `.env` uses MySQL (`projects_maganghub_db` on 127.0.0.1:3306, user `root`, empty password). `.env.example` defaults to SQLite and is only copied by `composer setup` when `.env` is missing.
- `composer setup` runs `migrate --force` immediately after copying `.env.example`. That config points at SQLite, and `database/database.sqlite` is gitignored — `touch database/database.sqlite` first if it is absent, or migrations fail with "Database file does not exist".
- `phpunit.xml` forces in-memory SQLite, so `php artisan test` never touches the local MySQL database.
- `RefreshDatabase` is commented out in `tests/Pest.php`; tests that touch tables must enable it (globally there or per file).

## Current scaffold state (verify before assuming)

The domain layer is generated scaffolding, not working code:

- Only `GET /` is registered (`php artisan route:list` shows one route). Header links to `/catalogue`, `/about`, `/contact` are dead.
- `Product`, `Category`, `News`, `ProfileBrand` each have a model, controller, FormRequest, policy, migration, factory, and seeder — but all method bodies are empty stubs.
- Every `FormRequest::authorize()` returns `false` and every policy method returns `false`. Routes wired to store/update/destroy will return 403 until authorization is implemented.
- Tables are flat: no foreign keys and no Eloquent relationships (e.g. Product ↔ Category).
- No Livewire components exist; views are plain Blade.
- Only `resources/views/layouts/app.blade.php` is functional, and it renders the header only (no footer). `layouts/main`, `layouts/catalogue`, `pages/about`, and `components/drumband` are empty files; `pages/catalogue` only has `@extends('layouts.app')` and no section. `components/footer` exists but is never included.
- `components/hero.blade.php` uses `asset('images/hero.jpg')`, but `public/images/` does not exist — the `hero.*` files under `public/build/assets/images/` are not served by that path. Add `public/images/hero.jpg` or change the asset path.
- The test suite is two trivial example tests; a green run only proves the app boots and `/` returns 200.

## Frontend

- `resources/css/app.css` is the only stylesheet: Tailwind 4 (`@import 'tailwindcss'`), `@source` entries for pagination and compiled Blade views, `@theme` for Instrument Sans, and brand CSS variables `--primary`, `--primary-dark`, `--light-blue`, `--text`, `--shadow`, `--radius`. Reuse those variables instead of hard-coded hex values.
- `resources/js/app.js` is empty, and `layouts/app.blade.php` loads CSS only via `@vite('resources/css/app.css')`.
- If `@vite` fails or points at `http://[::1]:5173`, either start `npm run dev` or delete the gitignored `public/hot` and run `npm run build`.
- `.npmrc` sets `ignore-scripts=true`, so npm dependencies that rely on postinstall scripts will not build automatically.
